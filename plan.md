1.  **Analyze Kotlin performance opportunity:** Found several instances where collections are being mapped then filtered for null and finally taking the first element, e.g., `.mapNotNull { ... }.firstOrNull()` or `.map { ... }.filterNotNull().firstOrNull()`.
2.  **Impact:** This approach creates intermediate collections mapping over every element in the collection, filtering out nulls, then just grabbing the first item. We can optimize this by replacing it with Kotlin's built-in `firstNotNullOfOrNull`, which applies the lambda and returns the first non-null result immediately without traversing the rest of the collection or creating intermediate collections.
